Как текут данные через этот сервис

Инициализация соединения:
При старте приложения NestJS создаёт единый инстанс RedisService. Клиент ioredis открывает TCP-соединение, включает оффлайн-очередь для буферизации команд при кратковременных сетях и настраивает автоматическое переподключение. Логгер фиксирует состояния подключения через события connect/error/close.

Поток записи (set с TTL):
Бэкенд передаёт объект рыночных данных → сервис сериализует его в JSON → отправляет команду SET key value EX 300. Redis сохраняет строку и ставит внутренний таймер на автоматическое удаление через 300 секунд. Бэкенд продолжает работу без ожидания подтверждения, так как await гарантирует выполнение, а void убирает лишний возврат типов.

Поток чтения (get):
Запрос на ключ → Redis возвращает сырую строку или null → сервис пытается JSON.parse. Если данные повреждены или ключ отсутствует, try/catch перехватывает ошибку, логирует её через Winston-совместимый Logger и возвращает null. Это позволяет MarketService корректно определить CACHE MISS и инициировать fallback на внешний API без падения потока.

Контроль свежести (pttl):
После успешного чтения или записи MarketService вызывает pttl(key). Redis возвращает миллисекунды до истечения TTL. Бэкенд вычисляет cacheAge и nextRefreshIn, упаковывает их в MarketResponse и отправляет фронтенду. Фронтенд использует nextRefreshIn для отрисовки прогресс-бара без дополнительных сетевых вызовов.

Защита от лавины (setNX):
При истечении TTL 100 000 пользователей одновременно попадают в CACHE MISS. MarketService вызывает setNX(lockKey, '1', 5). Redis атомарно проверяет существование ключа и создаёт его с TTL 5 секунд только при отсутствии. Первый воркер получает true, остальные получают false и переходят в режим ожидания. После короткой паузы они читают уже заполненный кэш. Это полностью исключает параллельные запросы к CoinGecko и защищает инфраструктуру от DDoS.

Жизненный цикл и логирование:
Winston интегрирован в NestJS через LoggerService, поэтому все вызовы this.logger.log/error/warn автоматически маршрутизируются в ваши Winston-транспорты (файл, консоль, внешний aggregation). При остановке сервера onModuleDestroy вызывает disconnect(), что гарантирует graceful-отключение без утечек соединений. Данные в Redis сохраняются независимо от жизненного цикла процесса, а при перезапуске новый инстанс подключается к тому же кластеру и продолжает работу с актуальным кэшем.
