КАК ТЕКУТ ДАННЫЕ (КРАТКО)
Транзакция → фон → атомарная запись 1h
CRUD коммитит сделку, мгновенно возвращает ответ и запускает rebuild() в фоне. Сервис проходит все сделки, считает стоимость, добавляет рыночный хвост из Redis и атомарно заменяет только часовые точки.
Cron → живая динамика + агрегация
Раз в час добавляется рыночный снимок. По расписанию запускаются rollup-джобы (1h→1d→1w→1m), создают старшие уровни и удаляют просроченные строки. Объём БД стабилизируется на ~322 точках/пользователь.
Контроллер → мгновенная выборка
API обращается к нужной гранулярности, выбирает 20–60 строк за 2–4 мс, прореживает с сохранением границ, отдаёт JSON.
Фронтенд → детерминированный рендер
React Query кэширует ответ, useMemo трансформирует в [timestamp, value], ECharts рисует логарифмическую кривую с жёсткими min/max оси X. Шапка показывает актуальную стоимость из последней точки.

## 📈 Модуль Аналитики (Portfolio Index & Snapshots)

### 🔹 Архитектурные гарантии

| Гарантия                 | Реализация                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------- |
| **Мгновенный UI**        | CRUD транзакций возвращает HTTP-ответ синхронно. `rebuild()` запускается fire-and-forget в фоне.        |
| **Атомарность истории**  | `prisma.$transaction([deleteMany, createMany])` гарантирует отсутствие "разорванных" состояний графика. |
| **Защита от дублей**     | Redis `SET NX EX` + проверка `last.timestamp > 4min` в кроне.                                           |
| **Бесшовные таймфреймы** | Fallback на `1h` при отсутствии rollup-данных. Пользователь никогда не видит пустой график.             |
| **Стабильный объём БД**  | Rollup-кроны (`1h→1d→1w→1m`) + cleanup старых точек. ~322 записи/пользователь в steady-state.           |

### 🔹 Поток данных (Data Flow)

1. **Транзакция → Фон → Атомарная запись `1h`**  
   `TransactionService` коммитит сделку → мгновенно отвечает клиенту → асинхронно вызывает `snapshotService.rebuild()`. Сервис проходит все сделки хронологически, считает баланс, подтягивает актуальные цены из Redis, формирует массив `1h` точек и атомарно заменяет старые.

2. **Cron → Живая динамика + Агрегация**
   - `*/5 * * * *`: добавляет рыночный снимок, если последняя точка старше 4 минут.
   - `0 5 * * *` / `0 10 * * 0` / `0 15 1 * *`: rollup-джобы создают старшие уровни (`1d`, `1w`, `1m`) и удаляют просроченные строки.

3. **Контроллер → Мгновенная выборка**  
   `GET /analytics/portfolio-index?range=...` маппит диапазон на гранулярность, выбирает 20–60 строк за 2–4 мс, прореживает с сохранением первой/последней точки, отдаёт JSON.

4. **Фронтенд → Детерминированный рендер**  
   React Query кэширует ответ (stale 30s), `useMemo` трансформирует в `[timestamp, value]`, ECharts рисует кривую с жёсткими `min/max` оси X. Кэш инвалидируется через `window.dispatchEvent` после успешной транзакции.

### 🔹 Метрики производительности

| Операция               | Время (p95) | Нагрузка                                 |
| ---------------------- | ----------- | ---------------------------------------- |
| `GET /portfolio-index` | 3–6 мс      | 1 SELECT + in-memory sampling            |
| `rebuild()` (25 tx)    | 40–80 мс    | 1 SELECT tx + 1 Redis HIT + 1 TX replace |
| `appendMarketSnapshot` | 15–30 мс    | Redis lock + 1 SELECT + 1 INSERT         |
| Rollup `1h→1d`         | <5 мс       | 1 SELECT + 1 INSERT + 1 DELETE           |

### 🔹 Масштабирование

- Модуль stateless. Redis выступает shared lock/cache.
- При >10k транзакций/пользователь рекомендуется добавить пагинацию в `rebuild()` или перейти на incremental snapshot diff.
- ECharts инициализируется с `renderer: 'svg'` для стабильного SSR-френдли рендера и низкого потребления памяти на мобильных устройствах.
