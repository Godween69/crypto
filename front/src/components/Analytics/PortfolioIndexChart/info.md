Как текут данные (кратко)
Инициация: Компонент монтируется → читает defaultRange → React Query отправляет GET /analytics/portfolio-index?range=1d.
Бэкенд: Контроллер маппит диапазон на гранулярность 1h → выбирает точки из БД → прореживает до 60 → кэширует в Redis → возвращает JSON.
Трансформация: useMemo преобразует ответ в [timestamp, value]. Если yAxisMode: 'index', берётся indexValue, иначе absoluteValue.
Рендер: useEffect инициализирует ECharts или вызывает setOption. Движок строит SVG-кривую, ось Y форматирует значения ≥10K в K, тултип показывает дату и доллары через строгое runtime-сужение.
Смена таймфрейма: Клик по кнопке → обновление range → новый queryKey → фоновый fetch → пересчёт chartSeries → плавная анимация перехода. keepPreviousData предотвращает схлопывание layout.
Ретроактивные правки: Изменение транзакции задним числом → IndexRecalcService пересчитывает точки от даты правки → сброс Redis-кэша → тихий рефетч React Query → график обновляется без участия пользователя.

# Portfolio Index Chart: Техническое описание

Автономный React-компонент для визуализации динамики стоимости портфеля. Отображает абсолютную стоимость в USD или нормализованный индекс на выбираемых таймфреймах. Работает без обращения к внешним историческим API, используя только внутренние снимки цен и транзакции.

## 🏗 Архитектура потока данных

### 1. Источники данных

• `Transaction` (PostgreSQL) — история операций BUY/SELL с метками времени.
• `MarketService` (Redis) — актуальные рыночные цены, обновляемые кроном каждые 5 минут.
• `PortfolioIndexPoint` (PostgreSQL) — готовые точки графика, сгенерированные фоновыми воркерами.

### 2. Генерация точек (Backend)

• `IndexGeneratorService` (каждый час) — считает остатки монет, умножает на цены из Redis, нормализует к `baselineValue`, записывает точку `1h`.
• `IndexRollupService` (по расписанию) — агрегирует `1h → 1d → 1w → 1m` через `LAST_VALUE`, удаляет устаревшие срезы, стабилизирует объём БД.
• `IndexRecalcService` (по триггеру) — при ретроактивном изменении транзакций удаляет точки от даты правки, пересчитывает остатки, выполняет bulk insert новых точек.

### 3. API-слой

• Эндпоинт: `GET /analytics/portfolio-index?range={1d|7d|30d|90d|1y|all}`
• Маппинг гранулярности: в dev-режиме все диапазоны используют `1h` для мгновенной доступности истории. В production планируется переход на агрегаты (`7d/30d → 1d`, `90d → 1w`, `1y/all → 1m`).
• Прореживание: API возвращает не более 60 точек на диапазон (равномерная выборка) для схематичности и производительности DOM.
• Кэширование: Redis, ключ `analytics:index:{range}`, TTL 300 сек.

### 4. Frontend-слой

• Запрос: React Query (`useQuery`) с `staleTime: 300_000`. Фоновый рефетч при истечении TTL. `placeholderData: keepPreviousData` предотвращает мерцание при переключении таймфреймов.
• Трансформация: `useMemo` преобразует JSON в массив `[timestamp, value]`. Выбор `indexValue` или `absoluteValue` управляется конфигом.
• Рендер: ECharts (SVG). `useEffect` синхронизирует данные с DOM. `ResizeObserver` адаптирует размер, `dispose()` очищает память.
• UI: Таймфреймы расположены под графиком по центру. Состояния загрузки/ошибки/пустоты рендерятся внутри фиксированного viewport, не ломая layout.

## ⚙️ Конфигурация (`index-chart.config.ts`)

Все визуальные и поведенческие параметры вынесены в иммутабельный объект. Изменение конфига не требует правки логики компонента.

• `ranges` — доступные таймфреймы (массив `{key, label}`)
• `defaultRange` — стартовый диапазон (`'1d' | '7d' | '30d' | '90d' | '1y' | 'all'`)
• `yAxisMode` — режим оси Y (`'index'` — нормализовано к 100, `'usd'` — абсолютная стоимость)
• `yAxis formatter` — форматирование шкалы Y (значения ≥ 10 000 автоматически сокращаются до `K`, например `$15K`, `$102K`)
• `xAxis formatter` — форматирование шкалы X (русская локаль, двухстрочный вывод месяца только 1-го числа, `hideOverlap: true`)
• `chart.type` — тип визуализации (`'line'` или `'area'`)
• `chart.smooth` — сглаживание кривой (`true` или `false`)
• `animation.*` — параметры перехода (`duration` в мс, `easing` — кривая плавности)
• `states.*` — тексты фолбэков (строки для загрузки, ошибки, пустого состояния)

## 🔍 Ключевые принципы

1. **0 внешних исторических запросов** — все точки строятся на основе цен из Redis, зафиксированных в момент генерации. CoinGecko вызывается только для актуальных котировок.
2. **Детерминированная нормализация** — `indexValue = (absoluteValue / baselineValue) * 100`. База фиксируется по первой транзакции. При ретроактивных правках база пересчитывается, индекс сохраняет консистентность.
3. **Многоуровневое удержание** — объём БД стабилен (~50 точек на пользователя). Старые уровни автоматически агрегируются и удаляются rollup-джобами.
4. **Чистый React** — вычисления в `useMemo`, DOM-синхронизация в `useEffect`, идемпотентность гарантирована. Компонент не принимает пропсы с данными и полностью автономен.
5. **Строгая типизация** — `any` полностью исключён. Форматтеры тултипов используют `unknown` + runtime-сужение. Конфиг иммутабелен (`as const`).

## 🛠 Troubleshooting

• **Пустой график на длинных таймфреймах** — rollup-кроны ещё не сработали, агрегаты отсутствуют. В dev все диапазоны работают через `1h`. В production достаточно дождаться расписания rollup-джобов.
• **Кнопки исчезают при пустом состоянии** — условный рендер возвращал фолбэк до обёртки. Исправлено: кнопки вынесены из условного блока, рендерятся всегда.
• **График не обновляется после правки транзакции** — Redis-кэш диапазона ещё не истёк. Подождите до 5 минут или сбросьте ключ `analytics:index:*` вручную.
• **Ошибка типов ECharts** — строгий TS конфликтует с обобщёнными типами библиотеки. Используется `unknown` + runtime-сужение в форматтере тултипа. `any` исключён.

## 📦 Интеграция

Компонент самостоятельно управляет запросами, кэшем, состоянием диапазона и жизненным циклом графика. Не требует пропсов или контекста.

```tsx
import { PortfolioIndexChart } from "./PortfolioIndexChart";
import { ChartPanel } from "../ChartPanel/ChartPanel";

<ChartPanel title="Динамика портфеля">
  <PortfolioIndexChart />
</ChartPanel>;
```
